# درگاه پرداخت رمزپال برای ووکامرس

افزونه‌ای مستقل و آمادهٔ استفادهٔ عملیاتی برای دریافت پرداخت تتر (USDT) در ووکامرس از طریق API رمزپال. این پیاده‌سازی از افزونهٔ زیبال فقط به‌عنوان مرجع تجربهٔ کاربری ووکامرس الهام گرفته و منطق اتصال، امنیت و مدیریت وضعیت آن بر اساس API رمزپال نوشته شده است.

## امکانات

- ساخت پرداخت و هدایت مستقیم مشتری به صفحه امن رمزپال
- تأیید سمت سرور مبلغ، شناسه پرداخت، شناسه سفارش و وضعیت `VERIFIED`
- سازگار با تسویه‌حساب کلاسیک و Cart/Checkout Blocks
- اعلام سازگاری با HPOS ووکامرس
- افزودن واحد پول USDT و امکان تبدیل نرخ ثابت برای فروشگاه‌های ریالی/تومانی
- زبان خودکار یا ثابت فارسی، انگلیسی و عربی برای صفحه پرداخت
- جلوگیری از ساخت درخواست تکراری با استفاده دوباره از لینک فعال
- ذخیره شناسه پرداخت و شناسه‌های تراکنش بلاک‌چینی در سفارش
- لاگ اختیاری و بدون کلید API، اطلاعات شخصی مشتری یا آدرس Callback
- تنظیمات و پیام‌های کاملاً فارسی و واکنش‌گرا

## پیش‌نیازها

- WordPress 6.2 یا جدیدتر
- WooCommerce 7.6 یا جدیدتر
- PHP 7.4 یا جدیدتر
- گواهی SSL معتبر و دسترسی خروجی HTTPS به `ramzpal.com`
- حساب پذیرنده و کلید API رمزپال

## نصب

1. فایل ZIP خروجی را از بخش Releases دریافت کنید.
2. در پیشخوان وردپرس به «افزونه‌ها ← افزودن افزونه تازه ← بارگذاری افزونه» بروید.
3. ZIP را نصب و افزونه را فعال کنید.
4. به «ووکامرس ← پیکربندی ← پرداخت‌ها ← رمزپال» بروید.
5. مطابق بخش بعد API Key پذیرنده را دریافت و در تنظیمات وارد کنید.
6. روش محاسبه مبلغ را انتخاب کنید.
7. ابتدا با یک سفارش واقعی کم‌مبلغ در محیط آزمایشی فروشگاه، کل مسیر پرداخت و بازگشت را بررسی کنید.

## دریافت توکن احراز هویت (API Key)

در مستندات رمزپال، توکن احراز هویت با نام `api_key` معرفی شده و افزونه آن را با هدر `Authorization: Bearer <api_key>` می‌فرستد. برای دریافت آن:

1. در [رمزپال ثبت‌نام یا وارد حساب خود شوید](https://ramzpal.com/login).
2. اگر هنوز پذیرنده ندارید، از صفحه [ساخت درگاه پرداخت/پذیرنده](https://ramzpal.com/profile/merchant/create) یک پذیرنده ایجاد کنید.
3. وارد بخش مدیریت پذیرنده‌ها شوید و پذیرنده مربوط به همین فروشگاه را باز کنید.
4. مقدار **API Key** آن پذیرنده را کپی کنید.
5. در وردپرس به «ووکامرس ← پیکربندی ← پرداخت‌ها ← رمزپال» بروید و مقدار را در فیلد «کلید API» قرار دهید.
6. تنظیمات را ذخیره کنید. خود کلمه `Bearer` را داخل فیلد ننویسید؛ افزونه آن را خودکار به هدر اضافه می‌کند.

این کلید با `payment_id` فرق دارد: API Key کلید ثابت و محرمانه پذیرنده است، اما `payment_id` برای هر پرداخت توسط رمزپال ساخته می‌شود. API Key را در تیکت عمومی، اسکرین‌شات یا کد قالب قرار ندهید. راهنمای کوتاه قابل ارسال به مدیر فروشگاه نیز در [docs/SETUP-FA.md](docs/SETUP-FA.md) قرار دارد.

## تنظیم مبلغ

API رمزپال مبلغ را به USDT و در بازه ۱ تا ۵۰۰۰ دریافت می‌کند.

- اگر قیمت محصولات فروشگاه USDT یا USD است، حالت «یک‌به‌یک» را انتخاب کنید.
- اگر واحد فروشگاه تومان، ریال یا واحد دیگری است، حالت «تبدیل با نرخ ثابت» را انتخاب و قیمت هر ۱ USDT را دقیقاً بر حسب همان واحد وارد کنید.
- نرخ ثابت به‌صورت خودکار از بازار به‌روزرسانی نمی‌شود. برای نرخ پویا می‌توانید از فیلتر `ramzpal_wc_payment_amount` استفاده کنید.

مبلغی که هنگام ایجاد پرداخت محاسبه شده در متادیتای سفارش ذخیره می‌شود و همان مقدار در مرحله تأیید به API فرستاده خواهد شد؛ تغییر نرخ پس از شروع پرداخت باعث مغایرت سفارش جاری نمی‌شود.

## Callback و امنیت

آدرس Callback خودکار ساخته می‌شود و نیاز نیست چیزی در پنل وردپرس کپی کنید. افزونه هیچ سفارشی را فقط با پارامترهای GET پرداخت‌شده نمی‌کند. پس از بازگشت، یک درخواست مستقل به `/api/v1/payment/verify` می‌فرستد و موارد زیر را تطبیق می‌دهد:

- `payment_id`
- `order_id`
- مبلغ دقیق ثبت‌شده
- `success: true`
- وضعیت نهایی `VERIFIED`

کلید API در گزینهٔ password ووکامرس ذخیره می‌شود. برای سخت‌گیری بیشتر در زیرساخت، دسترسی به `wp-admin` و پایگاه داده را محدود، نسخه پشتیبان منظم و HTTPS را اجباری کنید.

## گزارش فنی

در تنظیمات درگاه، «ثبت رویدادهای فنی» را فقط هنگام عیب‌یابی فعال کنید. گزارش‌ها در «ووکامرس ← وضعیت ← گزارش‌ها» با منبع `ramzpal` قابل مشاهده‌اند. کلید API، اطلاعات شخصی مشتری و URL بازگشت در گزارش نوشته نمی‌شوند.

## فیلترها و اکشن‌ها

- `ramzpal_wc_api_base_url` — تغییر نشانی پایه API برای تست یک mock server
- `ramzpal_wc_callback_url` — تغییر Callback نهایی
- `ramzpal_wc_payment_amount` — تأمین نرخ/مبلغ USDT به‌صورت پویا
- `ramzpal_wc_payment_payload` — افزودن یا تغییر فیلدهای درخواست ساخت پرداخت
- `ramzpal_wc_gateway_icon` — تغییر آیکن درگاه
- `ramzpal_wc_payment_created` — پس از ساخت موفق پرداخت
- `ramzpal_wc_payment_verified` — پس از Verify موفق و تکمیل سفارش
- `ramzpal_wc_payment_request_failed` — خطای ساخت پرداخت
- `ramzpal_wc_payment_verification_failed` — خطای تأیید پرداخت

نمونه نرخ پویا:

```php
add_filter( 'ramzpal_wc_payment_amount', function ( $amount, $order ) {
    $live_usdt_price = (float) get_option( 'my_verified_usdt_rate' );

    return $live_usdt_price > 0
        ? (float) $order->get_total( 'edit' ) / $live_usdt_price
        : $amount;
}, 10, 2 );
```

منبع نرخ پویا باید قابل اعتماد باشد و در برابر قطع سرویس، جهش نرخ و دادهٔ قدیمی محافظت شود.

## ساخت بسته انتشار

```bash
./bin/build-plugin.sh
```

بسته نصب‌شدنی در پوشه `dist/` ساخته می‌شود. فایل ZIP شامل یک پوشه ریشه با نام استاندارد افزونه است و فایل‌های توسعه‌ای را وارد بسته نمی‌کند.
